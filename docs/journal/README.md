# Project journal

A running log of how BlinkGuard is built: what was done, why, and what is next.

| File | Contents |
|---|---|
| [`decisions.md`](decisions.md) | Key technical and product decisions, with their reasons |
| [`entries/`](entries/) | One dated entry per work session |
| [`../../CHANGELOG.md`](../../CHANGELOG.md) | User-facing changes per version |

## How entries are written

Each session gets a file named `YYYY-MM-DD.md` in [`entries/`](entries/), with four short sections:

- **Goal**: what the session set out to do.
- **Done**: what changed, with links to commits or files.
- **Learned / problems**: issues hit and how they were solved.
- **Next**: what is left or comes next.

A decision that shapes the project, such as a technology choice, a scope cut or a privacy rule, also goes into `decisions.md` with its reason.
